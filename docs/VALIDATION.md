# 实车验收清单

本文用于把“软件已实现”和“实车已验证”分开。没有原始串口日志和硬件实测时，
不得把某项标记为通过。

## 固件基线

每次测试记录：

- Git commit；
- `App/app_config.h` 是否存在未提交修改；
- 烧录工具和固件生成时间；
- 电池节数、测试前后电压、赛道方向和传感器高度。

## P1 循迹验收

1. 使用同一个 commit 和配置连续完成 3 圈，不中途复位或重新摆车。
2. 保存从上电到停车的完整 USART2 9600 8N1 原始日志。
3. 正常运行期间 `TD=0`，证明 TX 队列没有丢字符。
4. 正常运行期间 `OV=0`，`DT` 应接近 10ms；若 `DT >= 20ms`，记录当时状态。
5. 正常赛道上 `F=0`；断开传感器或让全部输入持续有效时，应进入 `LOST` 停车并报告故障码。
6. 每个左直角记录进入/退出时的 `SUM`，确认不再因单帧噪声提前退出，也不长期超过目标。
7. `CORNER -> RECOVER -> FOLLOW` 后不得立即进入 `BLIND -> LOST`。

## 电气冻结条件

PCB 或最终线束下单前必须确认：

- 电池 2S/3S、满电电压、连接器和峰值电流；
- 电机堵转电流与 TB6612 实际模块/芯片能力；
- LM2596 是模块还是离散电路；
- 循迹和编码器的供电电压、输出高电平、推挽/开漏类型；
- 所有 5V 输出到 STM32 GPIO 的电平兼容性；
- PCB 尺寸、安装孔和连接器方向。

上述项目需要万用表、示波器或模块数据手册验证，不能仅由固件推断。
