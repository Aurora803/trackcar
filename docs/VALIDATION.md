# 实车验收清单

本文用于把“软件已实现”和“实车已验证”分开。没有原始串口日志和硬件实测时，
不得把某项标记为通过。

## 固件基线

每次测试记录：

- Git commit；
- `App/app_config.h` 是否存在未提交修改；
- 烧录工具和固件生成时间；
- 电池节数、测试前后电压、赛道方向和传感器高度。

## P1 循迹验收

当前状态：`LINE_CORNER_ENCODER_TARGET=495` 的冻结版本已经完成连续 5 圈现场实车验证，测试全程未改参数。现有串口文件只保存部分尾部状态，不能作为完整 20 个角点的日志证明；以下清单用于复现和正式展示留档。

1. 上电后不发送命令，确认模式为 STOP 且两个车轮保持停止。
2. 分别测试单字符 `1/0` 和带 CR/LF 的 `START/STOP`，确认返回对应 ACK。
3. START 后必须重新经历 200ms `LINE_STATE_START`，不能从旧 CORNER/BLIND 状态继续。
4. 在 FOLLOW、CORNER、BLIND 状态分别发送 STOP，确认底盘立即停止。
5. 正式展示复测时使用同一个 commit 和配置连续完成 3 圈，不中途复位或重新摆车。
6. 正式展示复测时保存从上电到停车的完整 USART2 9600 8N1 原始日志；已完成的 5 圈测试只保留了部分尾部日志。
7. 正常运行期间 `TD=0`，证明 TX 队列没有丢字符。
8. 正常运行期间 `OV=0`，`DT` 应接近 10ms；若 `DT >= 20ms`，记录当时状态。
9. 正常赛道上 `F=0`；断开传感器或让全部输入持续有效时，应进入 `LOST` 停车并报告故障码。
10. 每个左直角记录进入/退出时的 `SUM`，确认不再因单帧噪声提前退出，也不长期超过目标。
11. 允许出现 `CORNER -> BLIND -> RECOVER -> FOLLOW`，`RECOVER` 也可能短暂返回 `BLIND`；但必须能够重新捕线，不能最终进入 `LOST` 停车。

普通USART数据线无法判断蓝牙无线链路是否断开，因此本轮不包含断连自动停车；
若该能力是比赛安全要求，需要增加蓝牙 STATE 引脚或心跳超时机制。

## P2 OpenMV 独立子系统验收（仓库外）

独立版的第二控制器应由 OpenMV 完成红色色块识别，并直接控制一只 MG996R 做水平方向转动。STM32 不接收目标坐标，也不输出云台 PWM；两控制器之间没有 UART 或其他数据通信。

当前仓库没有 OpenMV 程序目录，以下项目只能在取得实际 OpenMV 脚本和硬件后人工验证，不能从本仓库标记为通过：

1. OpenMV 能稳定识别赛场红色色块，并对无目标、多个目标和误检给出可预期行为；
2. MG996R 只做水平转动，中心位、方向、机械范围和软件限位正确；
3. OpenMV 上电、重启或故障不会阻塞 STM32 接收 HC-05 命令和执行循迹；
4. STM32 上电、停止或重启不会让 OpenMV 等待任何 STM32 数据；
5. 实物接线中不存在 STM32 与 OpenMV 之间的 UART、软串口或隐含心跳依赖；
6. OpenMV/MG996R 的供电和机械负载满足要求，动作时不会使任一控制器异常复位。

## 电气冻结条件

PCB 或最终线束下单前必须确认：

- 电池 2S/3S、满电电压、连接器和峰值电流；
- 电机堵转电流与 TB6612 实际模块/芯片能力；
- LM2596 是模块还是离散电路；
- 循迹和编码器的供电电压、输出高电平、推挽/开漏类型；
- 所有 5V 输出到 STM32 GPIO 的电平兼容性；
- PCB 尺寸、安装孔和连接器方向。

上述项目需要万用表、示波器或模块数据手册验证，不能仅由固件推断。
