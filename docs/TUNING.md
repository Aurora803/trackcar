# 循迹调参与冻结记录

本文区分“当前校赛稳定配置”和“历史实验记录”。`school-competition-line-v1` 已完成连续 5 圈实车测试，循迹核心参数现已冻结，不再继续调参。

## 1. 当前校赛稳定配置

真实配置以 `App/app_config.h` 为准：

```c
#define LINE_CORNER_ENCODER_TARGET      495
#define LINE_RECOVER_CORRECTION_LIMIT   40
#define LINE_RECOVER_PWM                200
#define LINE_RECOVER_CENTER_CONFIRM_MS  250U
```

源码实际使用的编码器角点判定为：

```c
g_corner_encoder_sum >= LINE_CORNER_ENCODER_TARGET
```

同一套参数已现场连续完成 5 圈，全程未改参数。当前版本适合冻结用于校赛展示。

## 2. 冻结原则

校赛前不再修改：

- 角点目标、PWM、PID、RECOVER 参数；
- 状态机、传感器权重和直角识别逻辑；
- 电机方向、UART、定时器、GPIO 和工程配置。

出现现场差异时先检查是否为正确固件、供电、接线、传感器高度、轮胎和机械状态，不用临时改变冻结参数掩盖硬件问题。

## 3. 当前实车认识

常见恢复路径为：

```text
FOLLOW --TR=2--> CORNER --TR=7--> BLIND --TR=8--> RECOVER --TR=10--> FOLLOW
```

`RECOVER` 偶尔以 `TR=11` 再次进入 `BLIND`，之后仍可恢复。因此当前结论不是“所有角点状态链完全理想”，而是容错恢复已满足校赛展示稳定性要求，仍有恢复路径偏长的优化空间。

## 5. 历史调参方法（仅归档）

历史阶段采用过以下判读方法：

1. 先确认编译和烧录的固件版本；
2. 使用 `S/RAW/ERR/SUM/TR` 判断进入角点、退出和恢复路径；
3. 转过头时曾尝试减小目标值，转向不足时曾尝试增大目标值；
4. 每次只改变一个变量并进行多圈复测；
5. 不同时修改 PID、电机方向、传感器权重和引脚。

这些方法用于解释历史记录，不是当前版本的继续调参授权。

## 6. 日志判读参考

- `TR=2`：FOLLOW 进入 CORNER；
- `TR=7`：CORNER 进入 BLIND；
- `TR=8`：BLIND 捕线进入 RECOVER；
- `TR=10`：RECOVER 稳定回到 FOLLOW；
- `TR=11`：RECOVER 短暂丢线回到 BLIND；
- `SUM`：角点编码器累计值；
- `RCM/RLM`：恢复中心确认 / 丢线确认计时；
- `DT/OV/F/TD`：调度、传感器和串口队列诊断。

本次 5 圈测试仅保留部分尾部串口日志，不可据此宣称完整记录或证明 20 个角点。
