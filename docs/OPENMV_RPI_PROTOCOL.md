# 通信增强版边界参考：OpenMV / Raspberry Pi 视觉协议

> **不属于校赛独立运行分支。** 本文件只保留历史通信增强方案的接口参考，不能作为当前分支的接线、构建或验收依据。

## 当前独立版边界

校赛独立运行版采用两套解耦控制器：

```text
STM32：矩形循迹 + TB6612FNG + 编码器 + HC-05 启停/遥测
OpenMV：红色色块识别 + 直接控制 MG996R 水平云台
两者之间：无 UART、无其他数据通信
```

STM32 的 PA2/PA3 已用于 USART2 HC-05（9600 8N1），PA8/PA9 已用于 TIM1 电机 PWM。本分支不给 OpenMV 分配 STM32 串口或舵机 PWM，也不包含 STM32 视觉协议、目标跟踪模式和二维云台链路。

当前仓库没有 `OpenMV/`、`openmv/` 或其他可识别的 OpenMV 程序目录，因而不能从本仓库确认红色色块算法、MG996R 控制引脚、角度限制或运行结果。

## 历史通信增强方案（未实现）

若未来在另一个明确命名的通信增强分支中重新设计 STM32 与视觉主机通信，可将以下 ASCII 行作为需求讨论起点：

```text
$T,<x_err>,<y_err>,<valid>\n
```

示例：

```text
$T,-32,18,1
```

含义：

| 字段 | 说明 |
|---|---|
| x_err | 目标中心相对画面中心的水平偏差，左负右正 |
| y_err | 目标中心相对画面中心的垂直偏差，上负下正，具体可按视觉端定义调整 |
| valid | 1 表示识别到目标，0 表示目标丢失 |

上述格式只是历史提案，不表示当前代码中存在解析器、串口分配或云台控制。尤其不能通过打开某个宏就把独立版变成通信版。

## 切换到通信增强版前必须重新设计

1. 明确建立独立分支和验收目标，不在校赛独立运行分支上叠加；
2. 重新规划视觉串口，不能占用 PA8/PA9 电机 PWM 或 PA2/PA3 HC-05；
3. 重新核对 PWM、编码器、循迹引脚以及实时调度影响；
4. 明确是否仍保留 HC-05，避免把调试、蓝牙和视觉数据复用成无法验收的隐含链路；
5. 补齐视觉端源程序和双方故障隔离测试后，才能把通信能力写成已实现。
