# OpenMV / Raspberry Pi 视觉通信协议

## 当前接线版本

本版按照最新接线图更新后，PA2/PA3 已用于 USART2 调试串口，PA8/PA9 已用于 TIM1 电机 PWM，因此暂不启用视觉通信。

视觉通信预留到：

```text
当前无视觉串口分配；PA2/PA3 为 USART2 调试，PA8/PA9 为电机 PWM。
目标波特率：115200，8N1（仅为后续独立视觉串口规划）
```

视觉端连接方式：

```text
OpenMV/RPi 暂不接入。后续接入前需要重新分配串口，例如释放其他 GPIO 做 USART/软串口。
GND           -> STM32 GND
```

注意：当前 USART2 用于蓝牙调试，实际初始化为 9600 8N1；`VISION_UART_BAUDRATE=115200`
尚未接入任何独立 UART。PA8/PA9 已被电机 PWM 占用，不能再作为 USART1 视觉串口使用。
正式加视觉前需要重新规划通信引脚，不能仅打开应用宏就认为已经工作在 115200。

## 消息格式

视觉端发送 ASCII 行：

```text
$T,<x_err>,<y_err>,<valid>\n
```

示例：

```text
$T,-32,18,1
```

含义：

| 字段 | 说明 |
|---|---|
| x_err | 目标中心相对画面中心的水平偏差，左负右正 |
| y_err | 目标中心相对画面中心的垂直偏差，上负下正，具体可按视觉端定义调整 |
| valid | 1 表示识别到目标，0 表示目标丢失 |

## 后续建议

如果你要同时保留调试串口和视觉串口，建议二选一：

1. 重新规划视觉串口，不要占用 PA8/PA9 电机 PWM 与 PA2/PA3 调试串口；
2. 使用 STM32 的其他可用串口/软串口方案，但要重新核对与 PWM、编码器、循迹引脚的冲突。
