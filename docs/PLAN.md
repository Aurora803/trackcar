# 方案计划

## 1. 总体目标

搭建一个面向比赛/课程项目/后续扩展的 STM32 循迹小车代码框架，避免把所有逻辑堆进 `main.c`。底层硬件、可复用组件、业务控制逻辑分层隔离，后续增加视觉打靶、避障、蓝牙/上位机、多模式切换时尽量不重写底盘代码。

## 2. 分层架构

```text
main.c
└── App 应用层
    ├── app_robot        # 初始化、任务调度、模式管理
    ├── app_line_follow  # 循迹业务控制
    └── app_vision_target# 视觉打靶业务控制，预留

Components 组件层
├── chassis              # 差速底盘接口，屏蔽左右电机细节
├── tb6612_motor         # TB6612FNG 驱动封装
├── yahboom_tracker8_io  # 8路循迹 IO 采样与误差计算
├── pid                  # 通用 PID
├── vision_protocol      # OpenMV/RPi UART 协议解析
├── gimbal_if            # 云台抽象接口
└── gimbal_servo         # 舵机云台示例实现，默认未启用

BSP 板级层
├── bsp_gpio             # GPIO 配置
├── bsp_pwm              # TIM1 PWM，PA8/PA9 电机调速
├── bsp_encoder          # TIM2/TIM4 编码器模式
├── bsp_uart             # USART2，PA2/PA3 调试串口
├── bsp_systick          # 1ms 系统节拍
└── bsp_servo            # 可选云台 PWM，默认未启用
```

## 3. 功能阶段

### 阶段 A：底盘跑通

- TB6612 电机正反转、刹车、PWM 调速；
- 左右电机方向校准；
- 编码器计数方向校准；
- 串口输出调试信息。

验收：串口能看到左右编码器增量；左右电机可独立正反转；小车能直行。

### 阶段 B：矩形赛道 8 路循迹跑通

- 读取 8 路传感器状态；
- 根据权重计算黑线位置误差；
- PID 输出差速修正；
- 支持动态基础速度：直线快、偏差大时自动降速；
- 支持矩形状态机：FOLLOW / BLIND / CORNER / RECOVER / LOST；
- 直角弯使用传感器特征 + 编码器累计脉冲双保险。

验收：能稳定绕闭合矩形赛道行驶，四个 90° 直角弯不冲出，丢线后能短时间找回，长时间丢线能停车。

### 阶段 C：速度闭环优化

- 用编码器计算左右轮速度；
- 外环循迹给左右轮目标速度；
- 内环速度 PID 输出 PWM。

验收：电池电压变化、地面摩擦变化时速度更稳定。

### 阶段 D：视觉二维云台打靶（当前版本暂不启用）

- OpenMV 或树莓派负责视觉识别；
- 本版先不接视觉；后续若接 OpenMV/树莓派，需要重新规划串口，当前 PA2/PA3 已用于 USART2 调试，PA8/PA9 已用于电机 PWM。
- STM32 控制二维云台追踪目标；
- 底盘控制与云台控制独立。

验收：不影响循迹底盘时序；视觉帧丢失时云台停止或回中；目标有效时云台平滑跟踪。

## 4. 解耦原则

1. BSP 不知道“小车逻辑”，只负责外设。
2. 组件层不直接依赖应用模式，只提供稳定接口。
3. 应用层只调用接口，不直接操作寄存器。
4. 引脚集中放在 `app_config.h`，移植时优先改配置，不改算法。
5. 视觉打靶与循迹用不同 App 模块，避免一个功能改动影响另一个功能。
