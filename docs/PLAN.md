# 校赛项目计划与当前状态

## 1. 当前结论

`school-competition-line-v1` 的 STM32 矩形循迹底盘已完成连续 5 圈实车验证，测试期间未修改参数。循迹模块现标记为“已冻结、已完成连续 5 圈实车验证”，校赛前不再修改核心参数、状态机、引脚或底层配置。

稳定配置以源码为准：

```c
#define LINE_CORNER_ENCODER_TARGET      495
#define LINE_RECOVER_CORRECTION_LIMIT   40
#define LINE_RECOVER_PWM                200
#define LINE_RECOVER_CENTER_CONFIRM_MS  250U
```

角点编码器判定为 `g_corner_encoder_sum >= LINE_CORNER_ENCODER_TARGET`。旧文档中的 `450/550/600` 是历史实验参数，当前已停用，不代表校赛稳定配置。

## 2. 当前架构

```text
User/main.c
  -> App/app_robot.c          初始化、任务调度、模式切换
  -> App/app_line_follow.c    已冻结的矩形循迹状态机
  -> App/app_vision_target.c  视觉/云台预留，默认关闭

Components/                   底盘、电机、循迹、PID、视觉协议和云台组件
BSP/                          GPIO、PWM、编码器、UART、SysTick 和舵机底层
```

`App/app_config.h` 当前承担跨层配置角色。校赛前不再重构目录和配置入口。

## 3. 已完成工作

- 8 路数字循迹、固定左转直角识别和右编码器累计退出已投入实车运行；
- `LINE_CORNER_ENCODER_TARGET=495` 已完成连续 5 圈矩形赛道耐久测试；
- 全程未修改参数，现场观察确认小车连续完成 5 圈；
- 蓝牙 `START/1` 与 `STOP/0` 启停保留用于调试和展示；
- 状态迁移事件日志支持 `TR` 原因码；
- 角点后 `BLIND/RECOVER` 容错可重新捕获中心线；
- 当前版本满足校赛展示稳定性要求。

证据边界：串口工具只保存了部分尾部日志，因此不能写成“完整串口日志证明了 20 个角点”。

## 4. 实车状态机认识

常见实际链路为：

```text
FOLLOW --TR=2--> CORNER --TR=7--> BLIND --TR=8--> RECOVER --TR=10--> FOLLOW
```

部分情况下 `RECOVER` 会以 `TR=11` 短暂再次进入 `BLIND`，随后仍可捕线恢复。当前效果应表述为：角点后容错恢复机制能够有效重新捕获中心线，当前版本满足校赛展示稳定性要求，但仍存在恢复路径偏长的优化空间。

## 5. 冻结范围

校赛展示版本不再调整：

- `LINE_CORNER_ENCODER_TARGET`、PWM、PID 和 RECOVER 参数；
- 循迹状态机与迁移逻辑；
- UART、定时器、GPIO、电机方向和传感器权重；
- 工程配置与构建文件；
- `school-competition-line-v1` 标签。

若现场出现异常，优先检查电池、接线、传感器高度、烧录版本和机械状态，不现场改变冻结参数。
